# go.services.communication.dzen

Учебный стенд для сквозной демонстрации путешествия сообщения через распределённую систему.

**Цель проекта** — показать, как одно событие, клик читателя по автору, 
проходит путь от генерации до отображения на экране. На каждом шаге событие 
трансформируется, обогащается и превращается в полезные данные. 
Система состоит из нескольких сервисов-звеньев. Каждое звено имеет свою роль,
зону ответственности и свой язык общения с соседями.


### Демонстрирует

- Передачу событий через Kafka (3 брокера).
- Накопление и ежедневную агрегацию кликов по авторам в `ClickCounter`.
- Push-модель: `ClickCounter` раз в сутки отправляет статистику в `StorageGateway`.
- Единый шлюз к PostgreSQL: `StorageGateway` — единственная точка доступа к БД.

## Архитектура

```
ClickImitator → Kafka → ClickCounter → StorageGateway ← ClickDashboard → UI
                                            ↓
                                        PostgreSQL
```


| Компонент | Роль |
|---|---|
| `ClickImitator` | Генерирует клики и пишет их в Kafka |
| `ClickCounter` | Читает Kafka, агрегирует по авторам; раз в сутки (00:05 и 01:05) отправляет статистику в `StorageGateway` |
| `StorageGateway` | Шлюз к PostgreSQL: принимает данные от `ClickCounter`, отдаёт данные `ClickDashboard`; здесь же миграции |
| `ClickDashboard` | Отдаёт UI таблицу статистики за N дней (данные берёт у `StorageGateway`|

## Быстрый старт

1. `docker compose up -d` — поднимает PostgreSQL и Kafka.
2. Скопировать `.env.template` в `.env` и при необходимости поправить параметры.
3. Запустить сервисы: `StorageGateway`, `ClickCounter`, `ClickDashboard`, `ClickImitator`.

Порты по умолчанию:

| Сервис | Переменная | Значение |
|---|---|---|
| PostgreSQL | `DB_PORT` | `5432` |
| Kafka | `KAFKA_BROKERS` | `localhost:9092,localhost:9093,localhost:9094` |
| `StorageGateway` | `PORT_CLICK_STORAGE` | `8084` |
| `ClickCounter` | `PORT_CLICK_COUNTER` | `8080` |
| `ClickDashboard` | `PORT_CLICK_DASHBOARD` | `8085` |

## API

### StorageGateway

- `POST /stats` — приём статистики от `ClickCounter`.
  Тело: `{ "date": "YYYY-MM-DD", "stats": [{ "author_id": 1, "count": 10 }] }`
- `GET /dashboard?date=YYYY-MM-DD` — данные для дашборда за указанную дату.
- `GET /authors` — список всех авторов.


## Заключение

Проект показывает путь одного клика целиком: `ClickImitator` генерирует событие и пишет его в Kafka с ключом по автору, `ClickCounter` читает поток и агрегирует клики по авторам, раз в сутки отправляет накопленное в `StorageGateway`, тот сохраняет данные в PostgreSQL, а `ClickDashboard` запрашивает их у шлюза и отдаёт UI в виде таблицы за N дней.

В проекте задействованы несколько способов передачи данных: Kafka, HTTP, PostgreSQL и HTTP-ответ для статической страницы. На этом маршруте можно изучать работу Kafka и партиционирование по ключу, ежедневную агрегацию по расписанию, идемпотентную запись в БД, развязку сервисов через шлюз, миграции, graceful shutdown.

Ценность проекта в том, что он превращает абстрактные слова «распределённая система» в конкретный маршрут, который можно пройти от начала до конца, потрогать руками, сломать, починить и снова запустить.
